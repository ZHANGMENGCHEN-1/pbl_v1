# 平台数据库存储简要说明

本文针对 A/B/C 三个教学项目，以当前代码已实现的功能为准；云服务器是否已启用新增字段，取决于是否部署最新代码并重启后端。

## 1. 数据放在哪里

使用 SQLite，默认文件为 `backend/data/workspace.db`，实际路径由 `backend/.env` 中的 `DATABASE_PATH` 决定。部署在云服务器后，数据保存在该服务器的数据库文件中，不通过 Git 同步。

学生通过“班级＋学号”标识；入口区分 A/B/C 组；会话 ID 区分同一学生的多次学习。刷新页面会创建新会话，但后台旧数据保留。入口字段 `source_route` 与业务数据通过 `project＋session` 关联。

| 组别 | 入口标识 |
| --- | --- |
| A班 | learning-activities |
| B班 | teaching-agent |
| C班 | meaning-making |

| 活动1保存本轮分组作答 | 每本书所选组别、对应计算轮次、真实答案、是否匹配、尝试次数 | teaching_round_answers |
| 活动1提交最终结果 | 学生填写的组内数量、中心、实际计算结果和比较结果 | teaching_submissions |
| 活动2提交排序 | 完整卡片顺序、正确与否、反馈、尝试次数；错误排序也保存 | teaching_submissions |

| B/C班与小知交流 | 问题、完整回复、当前任务上下文、模型、提示词版本、时间和回复状态 | teaching_chats |

业务记录保存学生身份、会话和时间，能够通过记录 ID 将“活动操作→交付→感受调查→小知交流”关联起来。大模型的内部推理内容不保存给学生的聊天正文。

## 3. 感受调查记录说明

每份调查包含四个独立的 1–5 分原始值：难理解 `difficulty`、无聊 `boredom`、沮丧 `frustration`、自我效能 `self_efficacy`。不计算总分，第4题不反向改写后保存。

| 字段 | 含义 |
| --- | --- |
| student_survey_no | 同一入口、班级、学号的累计第几次调查，跨会话延续 |
| session_survey_no | 本次学习会话第几次调查 |
| activity_survey_no | 本会话当前活动第几次调查 |
| activity_number、submission_id | 对应活动1/2/3及哪一次交付 |
| questionnaire_version、response_mode | 问卷版本和滑块交互版本 |
| started_at、created、response_duration_ms | 窗口创建时间、服务器保存时间、到首次完整作答并点击保存的耗时 |

正常依次完成三个活动时，会话内调查次序为1、2、3。重复有效交付后再次调查会新增记录；同一交付的网络重试不会重复保存或增加次数。旧数据保留，无法确认的旧版本和耗时不会补造。

方便查看、导出的视图为 `teaching_state_measurement_records`，四题评分已展开为独立列，服务器保存时间显示为 `submitted_at`。

## 4. 保存规则与当前范围

- 后台保存每次有效提交，不覆盖前次答案；活动2错误排序也属于有效提交。活动1、3允许保存格式合格但与计算结果不一致的学生答案。“已完成”表示交付完成，不等于掌握知识。
- 服务器记录时间使用 UTC，显示时可转为北京时间。调查开始时间来自浏览器，作答耗时来自浏览器计时；不能据此推断整个活动的有效学习时长。
- 过程事件记录登记、进入活动、计算、上传、分析、交付、调查、主动求助、自动开场、回复结束、暂停和服务返回的失败等关键节点，不是全部点击的流水账。
- 当前不逐次记录拖动排序、每次滑块移动、每次输入修改、单独选列切换、鼠标轨迹或精确页面停留时长。这些内容通常只在保存、运行或提交时形成快照。
- 浏览器本地拦截的错误、没有发到服务器的断网操作不会形成后台失败事件。活动进入事件和暂停通知为尽力上报，不能当作绝对完整的行为日志。

完整字段及 SQL 查询示例见同目录 `DATA.md`。
